# Layer4Meter: Latent Compute Substrate Specification

## Thesis

**L4: Latent Compute Substrate** is the invisible machine work that happens below or beside the visible application/runtime layer.

It is not hidden magic compute. It is the measurable substrate activity generated by modern AI-native work: process scheduling, memory pressure, cache churn, Spotlight indexing, APFS snapshots, Time Machine deltas, file events, thermal throttling, GPU/media-engine work, Neural Engine/offloaded inference, background daemons, app telemetry, WindowServer composition, network retries, model caches, browser caches, and security services.

Normal apps observe:

```text
user action → app output
```

A Mac actually performs:

```text
user action → runtime → OS services → silicon/coprocessors/storage/indexes/caches/logs → output
```

Layer4Meter turns that fourth layer into a measurable receipt.

## Product

Name: **Layer4Meter**

Alternative name: **SubstrateReceipt**

Tagline:

> Quantify the invisible compute behind AI work.

The system captures visible production and invisible substrate activity, then binds both into receipts that can be scored, compared, verified, and attached to financeable artifacts.

## L4 Capture Stack

Layer4Meter measures five planes simultaneously.

### 1. Visual Plane

Captures what changed on screen:

- active app
- active window
- UI state checkpoints
- visible artifact emergence
- agent stuck loops
- before/after screenshots or privacy-safe thumbnails

Primary macOS anchor:

- ScreenCaptureKit for user-authorized screen/window/display capture.

Boundary:

- use checkpoint capture, not continuous surveillance by default
- redact by policy
- store hashes/thumbnails where possible instead of raw screens
- require explicit user permission

### 2. File Plane

Captures file-system production activity:

- folders changed
- files created
- files deleted
- file hashes changed
- build artifacts created
- cache growth
- repo-relevant file deltas

Primary macOS anchor:

- File System Events API for directory hierarchy change detection.

Boundary:

- FSEvents reports changes; the app still needs its own path filters, hashing policy, and redaction rules
- store path hashes when file names are sensitive
- separate source-relevant deltas from unrelated background churn

### 3. Process Plane

Captures execution activity:

- process spawns
- terminal commands
- child processes
- build tools
- scripts
- package managers
- agent runtimes
- security-relevant process events where permitted

Primary macOS anchor:

- Endpoint Security framework where entitlement and deployment model allow it.
- fallback: shell wrapper, local command logger, launch/task observation, Git hook records, process samples.

Boundary:

- endpoint-level visibility may require Apple entitlements and user approval
- do not make V1 depend on privileged monitoring
- V1 should capture commands and child process classes before attempting full endpoint telemetry

### 4. Power / Performance Plane

Captures machine cost:

- CPU time
- disk writes
- memory pressure
- network bytes
- wakeups
- QoS behavior
- thermal pressure
- hangs or crashes
- retry loops

Primary macOS anchors:

- MetricKit for app diagnostics/performance reports where applicable.
- powermetrics-style sampling for local CPU/power/QoS observations where permitted.
- system counters and process sampling for V1 approximations.

Boundary:

- do not promise exact energy attribution in V1
- record raw samples and make LCI weights adjustable
- separate app-owned metrics from whole-machine background noise

### 5. Time / Snapshot Plane

Captures before/after state:

- session start checkpoint
- session end checkpoint
- file existence proof
- snapshot delta
- artifact creation window
- temporal anchors

Primary macOS anchor:

- Time Machine local snapshots and APFS temporal state where available.

Boundary:

- local snapshots are temporal anchors, not permanent storage guarantees
- snapshot availability depends on APFS and Time Machine settings
- never claim recovery or retention beyond tested platform behavior

## Official Source Grounding

This spec is grounded in existing macOS instrumentation surfaces, not in speculative hidden compute.

- Apple documents ScreenCaptureKit as the framework for screen/window/display capture.
- Apple’s File System Events Programming Guide says the file system events API lets an app ask for notification when the contents of a directory hierarchy are modified and can determine whether directory contents changed since the app last examined them.
- Apple documents Endpoint Security as the framework for system security event monitoring.
- Apple documents MetricKit as the framework for metrics and diagnostics.
- Apple Support says Time Machine local snapshots copy changed files hourly, are stored on the same disk as the original files, are separate from backup-disk backups, and are kept up to 24 hours or until disk space is needed.

## Latent Compute Index

The first metric is **LCI: Latent Compute Index**.

Initial formula:

```text
LCI =
  α·CPU_seconds
+ β·GPU_or_media_activity
+ γ·disk_write_MB
+ δ·file_event_count
+ ε·process_spawn_count
+ ζ·network_bytes
+ η·memory_pressure_score
+ θ·snapshot_delta_MB
+ ι·screen_state_changes
+ κ·agent_idle_or_retry_time
```

The formula is intentionally adjustable. The first implementation should store all raw features and compute a simple normalized score. Weights can be recalibrated later.

## Baseline Subtraction

The breakthrough is not just logging. It is subtracting baseline from stimulated workload.

Layer4Meter should support three run modes.

### Idle Baseline

The Mac sits still for a fixed interval, for example five minutes.

Purpose: measure ordinary background system activity.

### Human-Only Baseline

The user performs a representative task manually without AI agents.

Purpose: estimate normal human-driven substrate cost.

### Agent Workload

Windsurf, Codex, Claude, ChatGPT, terminal agents, or local scripts perform or assist the task.

Purpose: measure the AI-agent workload.

Derived metric:

```text
Hidden Compute Lift =
Agent Workload LCI - Human Baseline LCI - Idle Baseline LCI
```

This estimates the extra substrate activity caused by AI-agent work.

## Business Metrics

Layer4Meter converts raw substrate activity into economic metrics.

```text
Cost per artifact = energy + time + API spend + disk growth + retry waste
Proof density = verified events / total events
Agent efficiency = useful output / latent compute lift
Waste ratio = retries + failed builds + dead loops / total substrate activity
Revenue readiness = artifact value / hidden compute cost
```

This makes the fourth layer useful for ranking workflows.

## Shards

A receipt should be sharded by evidence plane.

### visual.jsonl

Each row records a privacy-safe visual checkpoint.

Fields:

- timestamp
- active_app
- active_window
- checkpoint_label
- screenshot_hash
- redaction_policy
- visible_artifact_hint

### files.jsonl

Each row records file changes.

Fields:

- timestamp
- path_hash or path
- event_type
- before_hash
- after_hash
- bytes_delta
- role

### process.jsonl

Each row records relevant process events.

Fields:

- timestamp
- pid
- parent_pid
- executable_hash
- command_class
- working_directory_hash
- event_type

### power.jsonl

Each row records power/performance samples.

Fields:

- timestamp
- cpu_seconds
- disk_write_mb
- network_bytes
- memory_pressure
- wakeups
- thermal_state

### git.jsonl

Each row records repository state.

Fields:

- timestamp
- repo_path_hash
- branch
- head_commit
- staged_count
- modified_count
- diff_hash

### snapshots.jsonl

Each row records temporal anchors.

Fields:

- timestamp
- snapshot_id
- snapshot_kind
- anchor_hash
- delta_mb
- notes

## Acceptance Criteria

The MVP is complete when:

- a project session can be started and stopped
- file changes are recorded
- Git state is captured
- process or command events are recorded
- basic performance samples are recorded
- an LCI score is computed
- a `.l4receipt` folder is exported
- a Merkle root is generated from shard hashes
- a verifier command can confirm receipt integrity
- a human-readable report is generated

## Boundary Conditions

Layer4Meter should avoid overclaiming.

- L4 is not literal quantum or hidden physics.
- LCI is an accounting metric, not a universal physical law.
- Snapshots are temporal anchors, not permanent storage guarantees.
- Screen capture should be checkpointed and redacted by policy.
- Endpoint-level process visibility may require entitlements and permissions.
- ZK should only be claimed when there is an actual proof system and verifier.
- Metric attribution must be qualified as an estimate unless the source is app-owned and directly measured.
- Baseline subtraction estimates excess substrate activity; it does not prove all excess came only from an agent.
