**Reality Compiler** is the umbrella product/system layer.

**OverLanguage 2.0** is the grammar layer.

**SubQuantum Glyph Notation** is the alphabet/compression layer.

**LambdaReceipt** is the output artifact.

The master statement:

> Reality Compiler turns local work into verified transferable value.

Glyph form:

```text
Intent → ⧉◇@L → H@L Æ R Æ λ⁻¹ = ◎ → $
```

## Why Not Only OverLanguage?

OverLanguage still sounds like a language.

The system is bigger than a language. It compiles:

```text
intent → glyph → workflow → agents → files → substrate cost → proof → receipt → transferable value
```

into:

```text
verified artifact + receipt + lambda score + buyer packet
```

Therefore the correct top-level name is not the syntax name. It is the system name.

Reality Compiler should be designed like a real compiler stack, not like a loose prompt chain.

A normal compiler has:

```text

→ parser
→ intermediate representation
→ passes
→ optimizer

→ executable artifact
```

Reality Compiler has:

```text

→ Reality IR
→ proof/value passes

```

## Role Of Each Name

### Reality Compiler

Use this when speaking to buyers, investors, and product users.

Definition:

> A system that compiles local AI work into verified, transferable, financeable artifacts.

### OverLanguage 2.0

Use this when speaking about syntax, grammar, and source files.

Definition:

> A glyph-native grammar for declaring production workflows, proof requirements, agents, outputs, and economic targets.

### OverProgramming

Use this when speaking about philosophy.

Definition:

> Programming the production system, not only the software.

### SubQuantum Glyph Notation

Use this when speaking about symbolic compression and the alphabet.

Definition:

> A compact notation for representing file identity, proof, substrate cost, location, transferability, and value states.

### LambdaReceipt

Use this when speaking about output artifacts.

Definition:

> A receipt-bound artifact packet with transferability scoring and verification state.

### ReceiptOS

Use this when speaking about persistent proof ledgers.

Definition:

> The ledger layer for hashes, claims, signatures, Merkle roots, and verification receipts.

### LambdaBase

Use this when speaking about data infrastructure.

Definition:

> A database of artifact transferability, friction, buyer readiness, proof density, and value claims.

## Boundary Conditions

Reality Compiler should avoid overclaiming.

- It does not compile reality in a literal physical sense.
- It does not guarantee market value.
- It does not replace legal, security, or financial diligence.
- It does not prove claims without evidence.
- It does not make local artifacts transferable unless lambda friction is actually reduced.

The serious claim is:

```text
local work + evidence + receipt + reduced friction = transferable artifact packet
```
